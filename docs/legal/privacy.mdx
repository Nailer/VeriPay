## Public by design (on the blockchain)

Anything written to Monad is **permanent and public**:

| Data | Where |
|---|---|
| Buyer and seller account addresses | `Trade` struct, events |
| Order amounts and asset | `Trade`, events |
| Item description you type when paying | `Trade.metadata` |
| Timestamps, release/refund/dispute outcomes | `Trade`, events |

<Note>
  **Don't put personal information (phone numbers, home addresses, names) in "What are you buying?"** — it becomes public and permanent.
</Note>

## Stored by VeriPay (Supabase)

| Data | Purpose | Table |
|---|---|---|
| Shop name, link name, payout address | Seller links | `sellers` |
| Receipt email, amount, item, addresses | Card payments | `pay_intents` |
| Notifications | In-app alerts | `notifications` |
| Chat messages | Order and support chat | `chat_messages` |
| Push subscription endpoints and keys | Device alerts | `push_subscriptions` |
| Exchange orders incl. bank account details | Exchange settlement | `exchange_orders` |
| Page views, connect events, user agent | Analytics | `page_views`, `wallet_events`, `app_users` |

Access: server only, via the service-role key. Row-level security blocks public access.

## Processed by third parties

| Party | Data |
|---|---|
| Paystack | Card details (VeriPay never sees full card numbers), email, amount |
| Supabase | The database above |
| Vercel | Hosting logs |
| Alchemy | RPC requests (addresses, transactions) |
| Envio | Public chain data only |
| Browser push services | Encrypted push payloads |

## What VeriPay never receives

Your passkey, your private key, or full card numbers.

## Your choices

- Disable device alerts at any time.
- Request deletion of off-chain data via `support@veripay.store` (on-chain data cannot be deleted).
