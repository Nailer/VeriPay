## 1. Sign-in (Mera passkey)

```mermaid
sequenceDiagram
    autonumber
    actor U as Person
    participant P as Phone · passkey
    participant App as VeriPay page
    participant Mera as Mera library

    U->>App: Tap "Use Face ID / fingerprint"
    App->>Mera: create or get passkey with PRF
    Mera->>P: WebAuthn request
    P->>U: Fingerprint / Face ID prompt
    U-->>P: Approve
    P-->>Mera: PRF output · 32 secret bytes
    Mera-->>App: Deterministic seed from PRF
    App->>App: Derive the account on the device
    Note over App: Same passkey → same account,<br/>on any device that has it.<br/>Nothing is stored on our server.
```

`src/lib/mera.ts`, `src/lib/useSignIn.ts` — see [Passkey accounts](/architecture/passkey-accounts).

<Accordion title="In plain words" icon="lightbulb">
  You approve with your fingerprint; your phone produces a secret; VeriPay's page turns that secret into your account, on your phone. Nothing secret goes to VeriPay.
</Accordion>


## 3. Buyer pays — the core money path

```mermaid
sequenceDiagram
    autonumber
    actor B as Buyer
    participant Page as /pay/handle page
    participant API as VeriPay server
    participant PS as Paystack
    participant DB as Supabase
    participant M as Monad · via Alchemy

    B->>Page: Open seller's link
    Page->>API: GET /api/sellers?handle · GET /api/reputation/addr
    API-->>Page: Shop name · paid out · disputes · refunds
    B->>Page: Amount ₦ · item · email · fingerprint
    Page->>M: vNGN.balanceOf(buyer) ≥ amount? → resume, skip card
    Page->>API: POST /api/pay/intent
    API->>DB: INSERT pay_intents · status awaiting_payment
    API-->>Page: reference VP-intentId-timestamp36 · publicKey
    Page->>PS: PaystackPop with that reference
    B->>PS: Card details
    PS-->>Page: callback(reference)
    Page->>API: POST /api/pay/confirm { id, reference }
    API->>API: reference startsWith VP-id- ?
    API->>PS: GET /transaction/verify/reference (secret key)
    PS-->>API: success · NGN · amount (kobo)
    API->>DB: UPDATE status=paid WHERE status=awaiting_payment
    API->>DB: UPDATE mint_tx='pending' WHERE status=paid AND mint_tx IS NULL
    API->>M: vNGN.mint(buyer, amount × 10⁶)
    API->>DB: status=funded, mint_tx=hash
    API->>M: ensureGas: if balance < 0.08 MON → send 0.15 MON
    API-->>Page: { intent: funded, gasReady }
    Page->>M: allowance < amount ? approve(escrow, amount)
    Page->>M: createTradeWithToken(seller, item, vNGN, amount)
    M-->>Page: TradeCreated(id, buyer, seller, amount) · ~1 s
    Page->>API: POST /api/trades/log · POST /api/notifications
    Page-->>B: Receipt · order no. · reference · "Secured in 1.1s"
```

### Guards and what they prevent

| Step | Guard | Stops |
|---|---|---|
| intent | Seller address looked up from handle server-side | Browser redirecting funds to another address |
| intent | `seller.address === buyer` rejected | Paying your own link to farm reputation |
| confirm | Reference must start with `VP-<intent id>-` | Paying ₦2,500 and presenting that receipt for a ₦50,000 order |
| confirm | Paystack asked directly, server to server | A tampered browser claiming a payment that never happened, or paid less |
| confirm | `paidNgn + 1 ≥ expected`, `currency == NGN`, `status == success` | Short payments, wrong currency, failed charges |
| confirm | Status guard in SQL `WHERE` | Two simultaneous confirmations both delivering |
| confirm | `paystack_ref` is `UNIQUE` | One charge funding two intents |
| deliver | Single delivery slot (`mint_tx = 'pending'`) | Minting twice if a retry races the first attempt |
| deliver | Mint exactly the verified intent amount | Any mismatch between charged and locked |
| deliver | On failure, slot released (`mint_tx = null`) | A transient error permanently stranding a paid buyer |
| gas | Counted before sending, guarded on prior count; cap 3 | Becoming a free faucet; concurrent double top-ups |
| page | Resume when `vNGN.balanceOf ≥ amount` | Charging a buyer twice after an interrupted lock |

`src/lib/payments.ts`, `src/app/pay/[handle]/page.tsx`, `src/app/api/pay/*` — see [Card to escrow](/architecture/card-to-escrow).

## 4. Release (buyer confirms delivery)

```mermaid
sequenceDiagram
    autonumber
    actor B as Buyer
    participant Page as /trade/id
    participant API as /api/pay/gas
    participant E as VeriPayEscrow

    B->>Page: "I received my order — pay the seller"
    Page->>Page: readyToTransact(addr): balance ≥ 0.03 MON?
    alt balance low
        Page->>API: POST { address }
        API-->>Page: { ready }
    end
    Page->>E: releaseToSeller(id)
    E->>E: require buyer · require open
    E->>E: released = true · fee = amount×feeBps/10⁴
    E-->>Page: FeeCharged · FundsReleased(id, seller)
    Page->>Page: POST /api/trades/log action=released
```

## 6. Dispute and arbitration

```mermaid
sequenceDiagram
    autonumber
    actor P as Buyer or seller
    participant Page as /trade/id
    participant Chat as /api/chat
    participant E as VeriPayEscrow
    actor A as Arbitrator (admin console)

    P->>Page: "Report a problem" → "Freeze & request review"
    Page->>E: raiseDispute(id)
    E-->>Page: DisputeRaised(id, by)
    Page->>Chat: System message: money frozen, agent will review
    A->>A: ArbitrationPanel scans last 150 trades for disputed
    A->>E: resolveDispute(id, buyerBps)
    E->>E: toBuyer = amount×bps/10⁴ · toSeller = rest
    E-->>A: FeeCharged (seller share) · DisputeResolved(id, toBuyer, toSeller)
```

## 7. Automatic release (Chainlink CRE)

```mermaid
sequenceDiagram
    autonumber
    participant Cron as CRE cron · every 15 min
    participant WF as Workflow · cre/auto-release
    participant ESC as VeriPayEscrow
    participant FWD as Chainlink forwarder
    participant ARR as AutoReleaseReceiver

    Cron->>WF: Run
    WF->>ESC: latest block timestamp + nextTradeId
    loop Last 150 trade ids
        WF->>ESC: getTrade(id)
        WF->>WF: due = !released && !refunded && !disputed && now ≥ autoReleaseAt
    end
    WF->>WF: abi.encode(uint256[] dueIds) · sign report
    WF->>FWD: writeReport(receiver, report, gasLimit 500000)
    FWD->>ARR: onReport · only trusted forwarder accepted
    loop Each id
        ARR->>ESC: autoRelease(id) inside try/catch
        ESC-->>ARR: success → AutoReleaseSucceeded · revert → AutoReleaseFailed(reason)
    end
```

See [Auto-release](/architecture/auto-release).
