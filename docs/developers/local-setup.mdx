## Prerequisites

| Requirement | Why |
|---|---|
| **Node.js 20+** and npm | Next.js 16 |
| A free **Supabase** project | Sellers, intents, notifications, chat |
| A free **thirdweb client id** ([thirdweb.com/create-api-key](https://thirdweb.com/create-api-key)) | Sign-in and transactions |
| Optional: **Paystack test keys** | Card flow |
| Optional: a testnet **minter key** + your own vNGN | Card flow delivery |
| Optional: **Alchemy** Monad testnet URL | Reliable RPC |

<Accordion title="In plain words" icon="lightbulb">
  You need Node.js installed, a free database account (Supabase) and a free key from thirdweb. Card payments need a few more test keys, but you can browse and look up sellers without them.
</Accordion>

## Steps

<Steps>
  <Step title="Clone and install">
    ```bash
    git clone https://github.com/Nailer/VeriPay.git
    cd VeriPay
    git checkout hackathon/metropolis
    npm install
    cp .env.example .env
    ```
  </Step>
  <Step title="Create the database">
    In your Supabase project, open **SQL editor**, paste [`supabase/schema.sql`](https://github.com/Nailer/VeriPay/blob/hackathon/metropolis/supabase/schema.sql) and run it. It creates every table with row-level security on. See [Database](/developers/database).
  </Step>
  <Step title="Fill in .env">
    Minimum to boot:
    ```bash .env
    NEXT_PUBLIC_CONTRACT_ADDRESS=0x00bdf9fbc9f59cc6814bbc7a91b19bbad1517e6d
    NEXT_PUBLIC_THIRDWEB_CLIENT_ID=your-client-id
    SUPABASE_URL=https://YOUR-PROJECT.supabase.co
    SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
    ADMIN_PASSCODE=choose-a-strong-passcode
    ```
    All variables: [Environment variables](/developers/environment-variables).
  </Step>
  <Step title="Run">
    ```bash
    npm run dev                       # development, http://localhost:3000
    # or, for realistic performance:
    npm run build && npm run start
    ```
  </Step>
  <Step title="Smoke test">
    - Open `/seller`, type `adaeze-thrift` — you should see the demo shop (if your DB has it) or a "no seller" message.
    - `curl localhost:3000/api/reputation/0xEfD0497f4557b49E84369cfb884B6c7446e11aBA` → JSON with `source`.
    - `curl localhost:3000/api/pay/intent` → `{ deliveryAddress, cardProcessor, storage }`.
  </Step>
</Steps>

## Enabling the card flow locally

<Steps>
  <Step title="Paystack test keys">Set `PAYSTACK_SECRET_KEY` (`sk_test_…`) and `NEXT_PUBLIC_PAYSTACK_PUBLIC_KEY` (`pk_test_…`).</Step>
  <Step title="Your own vNGN">Deploy `contracts/test/VeriPayTestNaira.sol` from Remix; set `NEXT_PUBLIC_NGN_TOKEN_ADDRESS`.</Step>
  <Step title="Minter key">Set `PAY_MINTER_PRIVATE_KEY` to the deployer's **testnet-only** key; fund it with testnet MON.</Step>
  <Step title="Create a seller">Visit `/sell` in one browser profile, then pay the link from another.</Step>
</Steps>

<Warning>
  **Passkeys are bound to the hostname.** A passkey account created on `localhost` is different from one on `veripay.store`. WebAuthn works on `localhost` without HTTPS; other hostnames need HTTPS.
</Warning>

## The `.next` gotcha

<Danger>
  **Never run `npm run build` while `npm run dev` is running.** It corrupts `.next`. The symptom is misleading: every *nested* API route (`/api/admin/*`, `/api/exchange/*`, `/api/trades/*`) returns 404 while single-level ones still work — it once looked like "the admin passcode is wrong".

  **Fix:** stop the server, `rm -rf .next`, restart. **Prevent:** typecheck with `npx tsc --noEmit` instead of building while dev is running.
</Danger>

Dev mode also feels slow (per-route compilation, reset server caches). **Always demo with `npm run build && npm run start`** — pages and `/api/exchange/rates` serve in ~3 ms in production mode.

## Commands

| Command | Purpose |
|---|---|
| `npm run dev` | Development server |
| `npm run build` | Production build |
| `npm run start` | Serve the production build |
| `npm run lint` | ESLint |
| `npx tsc --noEmit` | Typecheck without touching `.next` |
| `cd contracts/test && npm test` | Contract suite |
| `node tests/e2e-pay.mjs` | End-to-end money path (needs a running server) |
