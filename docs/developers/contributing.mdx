## Branches

| Branch | Purpose | Serves |
|---|---|---|
| `hackathon/metropolis` | Current product (default branch on GitHub) | `veripay.store` (Vercel Preview domain) |
| `main` | Earlier production line | `monad-pay-lagos.vercel.app` |

Work on a feature branch off `hackathon/metropolis` and open a PR into it. Nothing reaches `main` without a deliberate decision to merge.

## Workflow

<Steps>
  <Step title="Branch">`git checkout -b feat/short-description hackathon/metropolis`</Step>
  <Step title="Build">Follow [Conventions](/developers/conventions).</Step>
  <Step title="Check">
    ```bash
    npx tsc --noEmit
    npm run lint
    cd contracts/test && npm test        # if contracts changed
    node tests/e2e-pay.mjs               # if the money path changed (server running)
    ```
  </Step>
  <Step title="Docs">Update the relevant page under `docs/` and `docs/docs.json` if you add one.</Step>
  <Step title="Commit">Conventional style: `feat:`, `fix:`, `docs:`, `test:`, `chore:` — e.g. `feat(cre): workflow runs end to end`.</Step>
  <Step title="PR">Describe what changed, how you verified it, and any user-visible copy.</Step>
</Steps>

## Rules

- **Never commit secrets.** `.env*` and `.deploy-tmp/` are gitignored; the repo is public.
- **Never rewrite or backdate history** on shared branches.
- Keep the README's pre-existing vs built-during table, AI disclosure, credits, addresses and setup steps intact.
- Chainlink files in `contracts/cre/` (`ReceiverTemplate.sol`, `IReceiver.sol`, `IERC165.sol`) are vendored **verbatim** — don't edit them.

## AI-assisted contributions

Claude Code was used substantially, under the founder's direction. Such commits carry a `Co-Authored-By: Claude` trailer. Keep disclosing AI assistance the same way.

## Reporting bugs

Open a GitHub issue with steps to reproduce, the page/route, expected vs actual, and any transaction hash. For security issues, see [Responsible disclosure](/security/responsible-disclosure) — don't open a public issue.
